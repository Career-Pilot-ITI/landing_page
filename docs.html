Chapter 01 · System Overview

Career Pilot Platform Documentation

An AI-powered, multi-modal career preparation, adaptive interview coaching, ATS optimization, and competitive screening platform engineered for the modern job market.

1.1 Abstract & Problem Statement #

The contemporary technical recruitment pipeline presents steep hurdles for emerging software engineers and career-transitioning candidates. Traditional preparation typically relies on fragmented tools: isolated CV builders, generic LLM prompts that suffer from hallucinations, static interview question lists with zero speech/delivery feedback, and opaque Applicant Tracking Systems (ATS).

Core Engineering Philosophy Career Pilot eliminates fragmented career preparation by providing an integrated feedback loop. Candidate CVs, target job postings, on-device vision/speech tracking, server-side RAG question generation, and structured STAR evaluation are unified into one persistent ecosystem.

1.2 Target Personas & Value Proposition #

Career Pilot serves six distinct user segments through tailored interaction paradigms:

Fresh Graduates & Entry-Level

Build interview confidence, master the STAR framework (Situation, Task, Action, Result), and identify real-world skill gaps before actual hiring rounds.

Transitioning Engineers

Pinpoint transferable competencies, receive automated CV refactoring against target role descriptions, and practice specialized track questions.

Senior Specialists & Tech Leads

Refine complex architectural explanations, system design phrasing, leadership storytelling, and delivery pacing.

Recruiters & Hiring Organizers

Create private, invite-only interview challenges to pre-screen cohorts with standardized AI evaluation metrics.

1.3 Business, Pricing & Virtual Coin Model #

Career Pilot uses a hybrid monetization model balancing recurring monthly subscription tiers with consumable virtual coins for compute-heavy AI actions.

1.4 Project Objectives #

  • Grounded Intelligence: Eliminate hallucination by constraining AI responses with PostgreSQL pgvector similarity search over verified curriculum data.
  • Multimodal On-Device Perception: Process camera gaze, posture, and speech pacing locally on device (MediaPipe & Whisper / Apple Vision) to guarantee low latency and user privacy.
  • Centralized Access Control: Enforce plan quotas, feature entitlement, and coin deductibility deterministically in core:access.
  • Cross-Platform Parity: Deliver native high-performance mobile clients for Android (Jetpack Compose) and iOS (SwiftUI) communicating with a robust Spring Boot 3 cloud backend.
Chapter 02 · System Architecture

High-Level System Architecture

A decoupled 4-tier distributed architecture spanning native mobile edge computing, cloud orchestration, vector retrieval, and persistent transactional storage.

Distributed Subsystem Topology

01
Client Edge Perception (Android Jetpack Compose / iOS SwiftUI)

Local media capture, MediaPipe face/gaze/pose estimation, Whisper/Apple speech recognition, and reactive UI state management.

02
Authoritative Cloud Gateway & Orchestration (Spring Boot 3 / Java 21)

Stateless JWT authentication, REST API controllers, business workflows, coin wallet ledger, and background worker queues.

03
Semantic Intelligence & RAG Layer (pgvector + Gemini 1.5 Pro)

Text embedding generation (768-dim), semantic question retrieval, grounded STAR evaluation prompts, and agentic follow-ups.

04
Transactional & Realtime Persistence (PostgreSQL 16 + Firebase)

ACID relational entities (Users, Subscriptions, Challenges, Transcripts), vector indexes (HNSW), and cloud push notifications.

Chapter 03 · AI & Machine Learning

AI & Perception Engine Pipeline

A hybrid AI architecture splitting high-frequency multimodal edge perception from server-side vector retrieval and large language model reasoning.

3.1 AI Modeling & Execution Boundaries #

To deliver real-time responsiveness without incurring excessive cloud costs or compromising user privacy, Career Pilot strictly delineates execution boundaries:

  • Edge Processing (On-Device): Real-time eye contact tracking, face orientation, smile detection, posture stability, and microphone audio capture are executed locally on the client at 30 FPS.
  • Cloud Processing (Backend RAG): Semantic CV embedding, resume-to-job ATS scoring, contextual question selection, and STAR qualitative evaluation are processed on the authoritative backend.

3.2 On-Device Computer Vision & Audio Tracking #

The vision subsystem computes key metrics during live interview practice sessions:

  • Gaze Stability: Computes the deviation angle of iris landmarks relative to the camera lens normal vector.
  • Posture Stability: Tracks shoulder alignment landmarks (MediaPipe pose points 11 & 12) to detect slumping, extreme fidgeting, or camera disappearance.
  • Speech Pacing: Calculates words-per-minute (WPM), detecting pauses longer than 3 seconds or speech exceeding 180 WPM.

3.3 Retrieval-Augmented Generation (RAG) Architecture #

Career Pilot uses PostgreSQL with the pgvector extension to store 768-dimensional question and concept embeddings. When generating mock interview questions or evaluating answers, candidate background context is retrieved via cosine distance matching.

SQL · PostgreSQL pgvector Similarity Query 
-- Retrieve top-5 most relevant interview questions grounded in candidate CV & target role
SELECT 
    q.id,
    q.question_text,
    q.difficulty,
    q.category,
    1 - (q.embedding <=> CAST(:candidate_context_vector AS vector(768))) AS similarity_score
FROM interview_questions q
WHERE q.track_id = :target_track_id
  AND q.difficulty = :difficulty_level
ORDER BY q.embedding <=> CAST(:candidate_context_vector AS vector(768))
LIMIT 5;

3.4 Agentic AI Evaluation & STAR Scoring #

Interview answer evaluations follow structured prompt constraints to produce deterministic JSON output containing scores (0-100) across 4 dimensions:

Dimension Weight Evaluation Criteria
Situation & Task (ST) 25% Clear articulation of the engineering problem, context, constraints, and business goal.
Action (A) 35% Specific technical steps taken by the candidate, tools chosen, architecture decisions, and individual contributions.
Result & Reflection (R) 25% Quantifiable metrics (e.g., latency reduced by 40%), outcome, lessons learned, and trade-off analysis.
Delivery & Communication 15% Pacing, structural clarity, filler word frequency, and technical vocabulary accuracy.

Chapter 04 · Functional Features

Core Platform Capabilities

Ten interconnected product pillars designed to support the user throughout their entire career-preparation journey.

4.1 CV Knowledge Hub #

Allows users to upload their active CV (PDF/DOCX). The backend extracts skills, experience timelines, educational background, and projects into structured JSON entities and semantic vector embeddings, making candidate profile context available across all modules.

4.2 Adaptive Mock Interview Practice Room #

Simulates real-world technical and behavioral interview sessions. Features track selection (e.g., Android, iOS, Backend, Quality Assurance), contextual question prompts, speech capture, on-device delivery cues, and instant feedback reports.

4.3 ATS Job Workspace & Gap Analysis #

Candidates can paste target job descriptions or enter job URLs. The engine computes semantic match percentage, highlights missing required keywords, flags hard skill deficiencies, and suggests actionable CV enhancements.

4.4 Asynchronous CV AI Optimization #

Long-running AI optimization jobs rewrite CV bullet points according to the Google X-Y-Z formula ("Accomplished [X] as measured by [Y], by doing [Z]"), improving ATS ranking without introducing ungrounded claims.

4.5 Tailored Cover Letter Generator #

Synthesizes the candidate's verified CV achievements with target role requirements to produce persuasive, professionally structured cover letters with 1-click clipboard copy and PDF export.

4.6 Session Performance Analytics #

Longitudinal analytics track user performance over time across multiple dimensions: average STAR score, technical accuracy, gaze stability, pacing consistency, and track-specific readiness percentiles.

4.7 Interview Challenges Arena #

Provides a competitive practice dimension with three primary modes:

Public Challenges

Community-wide competitions open to all users (including Free tier) with live leaderboards and scoring.

Private Challenges

Passcode/invitation-only screening challenges created by organizers or study groups for structured evaluation.

Host / Creator Mode

Max-tier feature enabling users to configure custom question sets, time limits, and review aggregate candidate performance.

Chapter 05 · Security & Access

Security, Entitlements & Wallet Engine

Enterprise-grade security policies, centralized feature gating, and a secure virtual coin transaction ledger.

5.1 Authentication & Security Architecture #

All client-server communications use TLS 1.3 encryption. User sessions are governed by stateless JSON Web Tokens (JWT) signed with HMAC-SHA256.

  • Access Token: Short-lived (15 minutes expiration) bearing user ID, active subscription tier, and role claims.
  • Refresh Token: Long-lived (30 days expiration) securely stored in Android EncryptedSharedPreferences / iOS Keychain.
  • Password Hashing: BCrypt with cost factor 12.

5.2 Centralized Entitlement Engine (`core:access`) #

To eliminate duplicate gating logic across mobile screens, the Android application delegates all permission checks to a centralized core:access module.

Kotlin · Centralized Feature Access Verifier 
class FeatureAccessManager @Inject constructor(
    private val userSessionRepository: UserSessionRepository,
    private val walletRepository: WalletRepository
) {
    suspend fun checkAccess(feature: AppFeature): AccessResult {
        val plan = userSessionRepository.getActivePlan()
        val coins = walletRepository.getCoinBalance()

        if (plan.tierRank < feature.requiredPlan.tierRank) {
            return AccessResult.PlanUpgradeRequired(
                current = plan,
                required = feature.requiredPlan
            )
        }

        if (feature.coinCost > 0 && coins < feature.coinCost) {
            return AccessResult.InsufficientCoins(
                available = coins,
                required = feature.coinCost
            )
        }

        return AccessResult.Granted
    }
}

5.3 Coin Wallet Economics & PayMob Integration #

Users can top up their virtual coin balance at any time via PayMob payment gateway (Credit/Debit Card, Mobile Wallets, Meeza). All transactions are recorded immutably in the PostgreSQL wallet_transactions ledger table.
